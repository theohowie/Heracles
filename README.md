# Heracles

**手机上的开发智能体** —— 一个跑在 Android 上的 AI 编程 App。

你打字（或按住说话）描述一个需求，它在你手机上的**真实工作区**里读代码、改文件、跑命令；
接上设备侧工具链之后，它还能**直接在这台手机上**把 Android 工程构建成可安装的 APK，
或者解包、修改、重打包别人已经装好的 App。

模型用**你自己的 API Key**（BYOK）跑在云端，手机上不加载任何模型 —— 装完 APK 只有几十 MB。

> **当前版本：v0.1.0**（2026-10-19）· 第一个公开版本，只发源码
>
> 这是 **alpha / 开发者自用阶段**的代码：仓库里**没有预编译 APK**，也没有发布流程，要自己从源码构建；
> 工具面、接口、UI 都还会改。已经验证过的、还没验证的、目前发现的问题，
> 都在 [现在是什么状态](#现在是什么状态2026-10-19) 和 [目前发现的问题](#目前发现的问题) 里逐条写清楚。

## 它有什么用

| 场景 | Heracles 怎么帮你 |
|---|---|
| **手边没有电脑，想改几行代码** | 把手机上的项目目录加成工作区，说清楚要改什么；它读文件、局部替换、改完把 diff 给你看 |
| **想从零做一个 Android 小 App** | 生成工程骨架 → 写代码 → **在手机上**走 `aapt2 → javac → d8 → 对齐 → 签名`，直接产出可安装的 APK（不需要电脑，也不需要 Gradle） |
| **想改一个现成的 APK** | 解包（资源或 smali）→ 改 → 重打包 → 签名 → 装回去，改的文案在界面上生效 |
| **想让 AI 带着上下文看代码** | 工作区里的文件能列、能读、能按文件名/内容搜索，长文件自动分段 |
| **只是想有个手机上的编程助手** | 不带工作区也能聊；多轮工具调用、任务计划、随时中断 |

工具面（模型能调用的动作）大致分四类：

- **文件与搜索**：列目录、读文件、写文件、局部补丁、按名查找、按内容搜索、建目录、删除/移动/复制、压缩/解压、撤销恢复（改/删前自动留快照）
- **执行与交互**：在设备上跑 shell 命令、记住项目偏好、向你提问、按需披露长尾工具
- **构建与逆向**：生成 Android 工程、构建 APK、反编译、重打包、签名
- **计划**：模型先给出一份任务计划，界面上按真实执行结果逐步打勾

---

## 界面与操作

- **会话页**：对话 + 工具调用卡片（点开能看参数和结果）+ 计划清单 + 流式状态条（「正在读文件」「正在执行命令」）+ 右侧用量面板（缓存命中率、上下文占用）
- **侧边栏**：工作区与会话的树形列表，可加多个工作区、随时切换
- **输入栏**：`+` 上传文件（文本/代码内容会拼进请求）；运行中继续输入会**排队**，`↑` 可插队立即发送
- **设置**：模型提供商（可存多套、随时切换）、设备权限、外观、会话

## 三步用起来

### 1. 装 App

目前没有 Release APK，需要自己构建（命令见 [从源码构建](#从源码构建)）。装好后要求 **Android 12（API 31）及以上**。

### 2. 配模型

`设置 → 模型 → + 添加`，填四样：

| 字段 | 说明 |
|---|---|
| **API 协议** | `OpenAI 兼容`（最常见）/ `Anthropic` / `Responses` |
| **Base URL** | 例如 `https://api.deepseek.com/v1`、`https://dashscope.aliyuncs.com/compatible-mode/v1`，也可以是自建 vLLM 或中转站 |
| **API Key** | 只存在手机本地（安全存储），只出现在请求头里，不进日志 |
| **模型名** | 可点「获取可用模型」从 `GET {baseUrl}/models` 拉列表 |

填完点「测试连通」，它会发一个只要 1 个 token 的最小请求，直接告诉你通不通。

> **建议选支持 function calling 的模型。** 原生工具调用是实测验证过的那条路；
> 不支持的模型会退回旧的文本 JSON 协议（能跑，但稳定性差一截）。

### 3. 加工作区，开聊

侧边栏 `⊕` 有两个入口：

- **选择文件夹**：用系统文件选择器（SAF）授权任意目录，包括 `/sdcard` 上你自己的项目
- **默认工作区**：App 自己的私有目录，不用授权，适合第一次试手

然后像跟人说话一样描述任务。它自己决定调哪个工具，每次调用在界面上是一张卡片；
越界的动作按权限档位处理：**允许 / 需要确认 / 拒绝**。

**长任务的样子**：构建一次 APK 要 1–3 分钟，期间 App 会起一个前台服务保住进程，
通知栏实时显示当前步骤；手机太热（44 °C）会主动**暂停** —— 这是设计好的保护，不是崩溃。

### 可选：解锁「在手机上构建 APK」

构建和逆向类工具依赖一套**设备侧工具链**：Termux 的 bionic 版 `openjdk-17` / `aapt2` / `d8` /
`apksigner` / `smali`，摊成一棵前缀树，约 **244 MB**。不装它，聊天、读写文件、搜索都照常，
只是构建/逆向类工具会明确报错（不会假装成功）。

一次性部署：在 PC 侧把 Termux 的 bionic 包装配成一棵前缀树，再推到设备
（默认位置 `/data/local/tmp/heracles/toolchain`，也可以用 `HERACLES_TOOLCHAIN` 指定别处）。
这部分装配脚本属于开发脚手架，不在本仓库内。

另外，**在设备上执行 shell 命令**这条路由需要 **Shizuku**（或它的增强分支 Stellar）：
装好 Shizuku 后在 `设置 → 设备权限` 里一键授权，页面会显示当前走的是哪条路由。

## 现在是什么状态（2026-10-19）

### ✅ 已经真机验证过的

在真机（Android 17）上实跑取证：

| 能力 | 结果 |
|---|---|
| **手机端无 Gradle 构建** | `aapt2 → javac → d8 → 进程内对齐 → 签名 → pm install`，产出 12,765 字节的可安装 APK，界面正常 |
| **APK 逆向** | 解包 → 改资源 / 改 smali → 重打包 → 签名 → 安装，改的文案在界面上生效 |
| **构建引擎在 App 进程内跑** | 前台服务 + Shizuku 路由 + 温度源 + 构建引擎，6.1 秒出产物，App 自己拆包核对条目 |
| **前台服务与通知栏** | 模型调用 `build_apk` 期间服务自启、通知文案随步骤变、结束自撤 |
| **温度熔断** | 44.5 °C → 暂停（0 步、不出产物）；41.3 °C → 放行 |
| **原生 function calling** | 真 Key（OpenAI 兼容中转）实测：模型用纯文本说话 + 原生工具调用成功执行 |
| **默认工作区** | 侧边栏内置，真机走通 |

### ⬜ 还没实现 / 还没验证

- **Anthropic / Responses 两条协议轨**：只有 OpenAI 兼容那条做过真 Key 验证，另外两条**没有真机证据**
- **从 UI 发起的完整构建**：只跑到 `prepare` 就被温度熔断打断（细节见下一节）
- **git 集成**：没有内置；设备上自己装了 git 的话，可以用 shell 工具跑
- **图片多模态**：UI 能上传图片，但模型只会看到文件名和字节数
- **机型覆盖**：只在一种设备上验证过
- **发布形态**：没有预编译 APK、没有 CI、没有 release 签名（release 变体暂用 debug key）

**质量门禁**：`./gradlew check`（658 项 Kotlin 单测 + 架构门禁 + lint）·
`flutter analyze` **0 issue** · Dart 92 项组件测试 —— 均为 2026-10-19 本地实跑全绿。

> 一句话：**现在适合愿意自己构建、不怕踩坑的开发者拿来读和试**，还不适合普通用户当成品用。

## 目前发现的问题

按用户能感觉到的现象列，越靠前越挡路。

| # | 问题 | 现象 / 影响 | 状态 |
|---|---|---|---|
| 1 | **从对话里发起的构建跑不到底** | 让它构建 APK，模型会自己 scaffold → 读文件 → 调 `build_apk`，但构建跑到 `prepare` 之后常被 **44 °C 温度熔断**打断，界面拿不到完整产物。同一条构建链在工具层单独跑是能出 APK 的 | 真机复现 1 次；待挑设备凉的时候重跑取证 |
| 2 | **一轮多个工具调用只执行第一个** | 模型一轮里同时调了 3 个工具时，只有第一个真的执行，其余回填「未执行」，于是要多花一轮 | 已知限制，未修 |
| 3 | **图片看不懂** | 附件可以选图片，但只把文件名/字节数发给模型（多模态通道未接） | 未实现 |
| 4 | **SAF 工作区不能删/移目录** | 通过文件选择器加的工作区里，目录的删除和移动被明确拒绝（SAF 的目录 delete 是递归语义，不敢默认允许）；文件级的删除/移动端到端也还没验 | 设计取舍 + 待验 |
| 5 | **手机 `/sdcard` 上已有项目的构建未验** | App 不能直接写用户 `/sdcard`，方案是「读进来 → 在 App 私有 staging 里构建 → 产物写回」，这条只在单测里通过 | 待真机验证 |
| 6 | **缓存命中率没达标** | 目标 > 90%，历史读数 83.8%，而且是"本地模型时代"的口径；换成云端后**必须重测** | 欠账 |
| 7 | **shell 写出来的文件 App 可能读不到** | 模型用 `run_shell_command` 建的文件权限是 `0660`/目录 `0770`，外置存储上 App 自己再读可能被拒 | 已知边界，真机暂未踩到 |
| 8 | **侧边栏空态有个进不去的入口** | 「已有工作区但没有会话 + 开着筛选」时，「使用默认工作区」按钮不可达，只能看到"这个筛选下没有会话" | 已知 UI 缺口 |
| 9 | **长任务有轮次上限** | 单个任务有最大轮次（云端默认 40 轮），超了会被截断并提示，长任务需要拆开 | 设计行为 |
| 10 | **只在一种机型上验证** | 目前只验过 Android 17 一类机型；其它机型的温度、权限、文件系统行为都没有数据 | 待扩 |
| 11 | **开发机上 `flutter test` 跑不完** | 部分 Windows 机器上会因本地回环被拒（`errno 10013`）或插件通道未 mock 而卡死；建议按单文件跑 | 环境问题，非代码缺陷 |

## 设计上值得一看的地方

- **会话严格 append-only**：从不改写历史消息，只往后追加 ⇒ 云端前缀缓存命中率 95% 以上，
  长会话的代价随轮次几乎不变（同样的法则在本地推理时代把第二轮从 26.7 秒压到 2.1 秒）。
- **抗幻觉靠架构，不靠提示词**：工具白名单 + 参数门禁三态（允许/需确认/拒绝）+
  解析失败绝不猜（不执行、如实回告）。
- **手机端不依赖 Gradle**：直接调 `aapt2` / `javac` / `d8`；APK 对齐由**进程内** `ZipAligner` 完成
  （Android 上根本没有 `zipalign` 这个二进制），且对齐结果要自校验。
- **核心逻辑在 Kotlin，不在 Dart**：AgentLoop、会话、前缀构建是纯 JVM 模块，
  在 PC 上毫秒级回归；前端只负责 UI 和通道。
- **后端可插拔**：provider 专有字段只在 provider 内部翻译，不泄漏到上层装配处。

更细的设计取舍与实测数据属于开发笔记，不随仓库发布。

## 从源码构建

**要求**：JDK 21、Flutter 3.44.2、Android SDK、adb。

```bash
# 核心：会话 / 缓存 / provider / 工具面 / 构建引擎（纯 JVM，不依赖 Android）
./gradlew check

# 前端
cd app
flutter pub get
flutter analyze
flutter test
flutter build apk --debug --target-platform android-arm64   # 产物：build/app/outputs/flutter-apk/app-debug.apk
adb install -r build/app/outputs/flutter-apk/app-debug.apk
```

Windows 用 `gradlew.bat`。⚠️ 同一条命令链里**不要连着跑多个 gradle 任务**（daemon 抢端口会假失败）——
逐条跑，看退出码。`flutter test` 在个别机器上会卡死（见问题 11），此时改成单文件跑。

## 注意事项

- **BYOK，费用自负**：所有推理都走你自己的 API Key；模型能力直接决定体验上限。
- **自动执行有风险**：它会在你授权的工作区里改文件、跑命令。请在工作区里放项目，不要授权敏感目录。
- **构建/逆向需要额外部署**：没装设备侧工具链时，相关工具只会失败并说明原因。
- **接口会变**：alpha 阶段没有兼容性承诺，会话格式也可能调整。
